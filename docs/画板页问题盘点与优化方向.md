# 画板页问题盘点与优化方向

> 状态：仅盘点，未改代码。结论基于**扣真实代码**（`public/modules/board.js` / `board_viewport.js` / `board_state.js` / `shotPlanDialog.js` / `styles.css` 20665+）+ 三张截图 + 行业对照。
> 用途：先定方向、再决定要不要动代码。

---

## 一句话结论

画板现在是**"长得像节点画布、用起来是固定流水线"**：付了 pan/zoom/minimap/连线/LOD 一整套画布开销，却没拿到画布的收益（不能拖节点、选中没用）。先修几个"看起来就坏了"的硬伤（漏串、死按钮、缩小全空），再补画布最核心的"选中→能干事"闭环。**不建议**现在投入"自由拖动节点/自由连线"。

---

## 现状（代码事实，先对齐）

- 画布 = 4 类节点，固定 4 列自动布局：`参考图 → 镜头计划 → 片段×N（竖排）→ 视频×N`（`board_state.js layoutBoard`）。
- 交互只有**平移 / 缩放 / 视口裁剪**（`board_viewport.js`）。节点位置是算出来的，**不能拖动**；`onPointerDown` 命中节点直接 return（除非空格/抓手）。
- 缩放 <40% 进入 `overview` LOD：CSS `display:none !important` 把缩略图/步骤/按钮全隐藏，只剩大标题（`styles.css:20810-20819`）；且 overview 下缩略图**根本不加载**（`shouldLoadThumb`）。
- 镜头编辑是另开的**全屏 modal**（`shotPlanDialog.js`），和画布空间模型脱节。
- 相机（缩放位置）按项目存 localStorage。

## 问题清单（按你要的三类 + 优先级）

### P0｜现在就"显得坏了"（代码实锤，优先修）

**1. 开发串 `缺 shotUid` 直接漏给用户** —— `board.js:908`
截图2里每个片段每一行都写着"缺 shotUid"。当 `shotUidOf(project, idx)`（`board_state.js:61`）取不到值时，整行的"生成图片/上传图片"动作**全部消失**，只剩一句用户看不懂的字段名报错 → 该片段直接**没法操作**。
- 方向：先查 shotUid 为什么解析不到（`shots[idx].shotUid`/`shot_uid` 是否真的没写盘）；UI 上无论如何都不能暴露字段名，缺就降级成"重试/占位/去镜头计划补齐"的人话提示。

**2. 成排死按钮，全在入口第一眼** —— `board.js:432-433 / 859 / 869`
撤销/重做工具（`disabled title="下一阶段接入"`）、参考图节点的"导入参考图"、"生成镜头计划"（`disabledButton`）都是点不动的占位。用户从左往右读，第一屏就是一排灰按钮 + 一句"下一阶段接入"。
- 方向：能接线就接，接不了就**先隐藏**，别把"下一阶段接入"留在正式界面。行业（React Flow / ComfyUI）：节点上只放"当下能用"的操作。

### P1｜高频体验债

**3. 选中节点几乎没用** —— `board.js onViewportClick` + `zoomToSelection`
点节点只做两件事：加一圈高亮、允许"缩放到选中"。没有详情面板、没有上下文操作。画布最该有的"**选中 → 看详情/改参数/操作**"闭环是缺的。
- 行业（React Flow 官方建议）：节点保持单一职责，额外逻辑放**侧栏 inspector**；选中时**弱化其他节点**突出当前。
- 方向：加右侧或浮层 inspector——选中片段=一屏看到"镜头首帧候选 + 镜头参数 + 视频候选"，把现在散在节点里的操作收进来。

**4. 缩小到看全局时，画面全消失** —— `board_viewport.js LOD_OVERVIEW_ENTER=0.4` + `styles.css:20810`
截图1的 39% 已经是 overview 态：只剩"片段1 / 封面占位 1/1 / 视频 已生成"这种文字，**没有任何缩略图**。用户"缩小 = 想看全片长啥样"，结果啥画面都看不到，只能靠 minimap 摸。
- 行业（Figma）：缩小是"看全貌"，缩略图恰恰是导航锚点，不该在此时被藏。
- 方向：overview 保留首帧缩略图，只隐藏文字/按钮/次要信息。

**5. 视频节点信息过载，且重复 12 遍** —— `board.js renderVideoModeSelector`
每个视频节点都常驻"全能参考 / 智能多帧 / 首尾帧"三个按钮 + "生成新视频"。术语晦涩（普通用户不懂这仨差别），还在 12 个片段上各摆一遍。
- 行业（ComfyUI 教训）：把高级参数塞进每个节点 = 认知过载，正是它被吐槽的点。
- 方向：默认收敛到 auto，模式选择进"更多参数"或选中后的 inspector；节点上只留主操作。

**6. 画布大片空 + 入口漂浮** —— `board_state.js layoutBoard`（`y=(stackH-refH)/2`）
参考图/镜头计划按整列高度垂直居中；12 个片段时，这俩节点浮在画布中部，上下大片空白，和右侧片段流视觉上断开。入口既不显眼，死按钮又正好在这。
- 方向：把"参考图 / 镜头计划"从自由画布里拿出来，固定成左侧 rail 或顶部 stepper（它们本就是全局阶段，不是可自由摆的节点）。

**7. 画布 ↔ 弹窗，两套心智** —— `shotPlanDialog.js`
"镜头计划"点开是全屏 modal 编辑器，和画布的空间/缩放模型完全脱节；改完关掉再回画布。用户在"空间画布"和"表单弹窗"之间反复横跳。
- 方向：镜头编辑做成画布内联/侧栏；短期至少让 modal 从被点的节点位置展开，保持视觉连续。

### P2｜方向与打磨

**8. "画板"名不副实**（见下方"方向判断"）——有全套画布开销，无拖动/连线/选中收益。
**9. 候选可拖排但无提示** —— `board.js onCandidateDragStart`，卡片 `draggable` 却没有拖拽把手/hover 暗示。
**10. 帮助偏极客** —— 面板里是 `Shift+1/2`、`0`、空格（`board.js:445-451`）。Mac + 非技术用户不友好，而这还是"全览/聚焦"的唯一提示入口。
**11. 参考图卡片重度 `backdrop-filter: blur(24px)`** —— `styles.css:20826`，大画布上是持续合成开销，且与其它卡片风格不统一。

## 方向判断（这一题建议你拍板）

**开放题**：画板到底要不要做成"真·节点画布"（可拖节点、可连线）？

行业信号很一致：

| 产品 | 画布形态 | 面向的人 |
|---|---|---|
| **ComfyUI** | 自由节点图 | 技术玩家；且非技术用户觉得"一团线"压力大，正在 retrofit **App Mode** 把节点图**藏起来** |
| **Flora** | 自由节点画布 | "想自己连模型"的技术型创作者 |
| **LTX Studio**（和 Origin 最像的对手，同样"脚本→视频"、面向非技术创作者）| **不用**自由节点图，用结构化 board/panel/frame + **每格内联重生成**（"re-render any single panel without disturbing the rest"） | 非技术创作者 |

Origin 的用户画像更接近 LTX 那一类。**我的判断：现在不要投入"自由拖动节点 / 自由连线"**——成本高，且和"受约束的线性流程 + 非技术用户"两头都不搭。把画布定位成"**自动布局的引导式流水线 + 可缩放总览**"，钱花在四件事上：
1. 选中 → inspector 闭环（P1-3）
2. 修死按钮 / 漏串（P0-1、P0-2）
3. 驯服 LOD，缩小仍能看缩略图（P1-4）
4. 收敛每节点术语（P1-5）

这样既保住你要的"一眼看全片"总览价值，又补上"选中能干事"这个画布真正的核心闭环。
若未来确有"一个镜头下多视频候选做 A/B 树、非线性探索"的需求，再把"自由画布"作为**单独大方向立项**，不混在这轮里。

## 行业对照要点（备查）

- **React Flow**：节点单一职责，额外操作进侧栏/ tooltip；选中弱化其余节点；minimap 可做成可点可拖导航；节点按类型上色。
- **ComfyUI 的反面教材**：节点图对非技术用户=认知过载，"7 个节点做本该 1-2 个节点的事"；解法是 App Mode / 图标 / 内置文档。
- **LTX Studio**：project→board→frame 三层；角色锁定保连续性；**单格内联重生成不动全局**；storyboard 直接流入视频时间线；拖拽重排 frame。
- **Figma 无限画布**：打开默认 zoom-to-fit；缩小=看全貌，缩略图是导航锚点。
- **候选/变体画廊**：一次多张、并排比、选最优、快速迭代——和 Origin 的"候选卡"方向一致，值得强化选优/对比。
